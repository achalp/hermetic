## What this feature does

The Artifacts panel's **Code** tab is now an editable CodeMirror editor (Python syntax highlighting). The user can:

- Edit the generated Python code
- Click **Re-run** to execute the edited code in the sandbox (no LLM call)
- The new artifacts (results, chart_data, datasets) populate the **Data** tab
- Click **Discard** to revert to the original code

The **SQL** tab remains read-only (warehouse SQL is regenerated by the LLM, not edited).

### SQL edit-rerun behavior

When the data source is a warehouse (an `artifacts.sql` is present):

- The SQL tab becomes editable in CodeMirror (was read-only)
- Re-run + Discard buttons appear when the SQL is dirty
- Re-run sends `context.sql` to `/api/query`; the server skips NL-to-SQL generation and uses the edited SQL
- The result CSV is re-extracted (schema may have changed); Python code-gen runs against the new shape
- The dashboard rebuilds from scratch via the standard streaming pipeline

The `onRequestRerun` callback signature evolved from `(code: string) => void` to `(edits: { code?: string; sql?: string }) => void` to accommodate both edit types. Page state's `RERUN_WITH_EDITED_CODE` action was renamed to `RERUN_WITH_EDITS` and now carries optional `code` and `sql`.

### How the dashboard rebuild works

When a parent passes `onRequestRerun` to the artifacts viewer (which page.tsx now does), clicking **Re-run** calls the parent instead of `/api/query/rerun`. The parent dispatches a new `RERUN_WITH_EDITED_CODE` action that:

1. Sets `pageState.rerunCode` to the edited Python.
2. Bumps `pageState.questionSeq`.
3. Closes the artifacts panel.

ResponsePanel sees the bumped `questionSeq` and sends the existing question to `/api/query` with `context.code` set to the edited code. The server's `/api/query` route now checks for `context.code`: when present, it skips the code-gen step and runs `runPipelineWithCode` instead of `runPipeline`. The rest of the pipeline (cache artifacts → stream UI compose) is unchanged. The dashboard area shows the standard "composing…" stepper, then renders the fresh dashboard.

The `STREAM_END` action clears `rerunCode` so a subsequent fresh question doesn't accidentally inherit edited code.

## Manual smoke test

### Setup

1. Start dev server: `npm run dev`
2. Upload any CSV (e.g. `data/test-fixtures/tier-1/follow-up-suggestions/sales-2024.csv`)
3. Run any analysis (e.g. _"What are total sales by region?"_)
4. Wait for the dashboard to render
5. Click the Artifacts button (or whatever toggles the panel) to open the bottom sheet
6. Click the **Code** tab

### Test 1 — happy path

1. Edit a line in the Python code, e.g. change a column reference or a filter threshold
2. Observe the toolbar: a "Re-run" button (accent color) and "Discard" button appear; "edited — re-run or discard" message shows
3. Click **Re-run**

**Pass:**

- Within ~5–15 seconds (sandbox execution time), a green "✓ executed — see Data tab" message appears
- The Data tab now shows the new computed values
- Clicking **Export XLSX** downloads the new dataset

### Test 2 — Discard restores

1. After editing the code (without running)
2. Click **Discard**

**Pass:**

- The editor reverts to the original code
- Re-run / Discard buttons disappear (code is no longer dirty)

### Test 3 — error path

1. Edit the code to introduce a Python error (e.g. `1/0` or a misspelled column name)
2. Click **Re-run**

**Pass:**

- The button briefly shows "Running..." then a red error message replaces it
- The error includes the line number and exception type from the sandbox
- The original artifacts are unchanged
- The user can fix the code and re-run

### Test 4 — read-only SQL tab

1. With a warehouse-sourced analysis active, switch to the **SQL** tab

**Pass:**

- The SQL renders with syntax highlighting
- The editor is read-only (no cursor caret, no edits possible)
- Re-run button is not shown
- Copy + Download .sql still work

### Test 5 — bundle size

1. Open the dev server's network panel
2. Check the size of the chunk that loads when opening the Code tab

**Pass:** the CodeMirror chunk is < 250 KB gzipped (CodeMirror minimal + lang-python + lang-sql + oneDark).

### Test 6 — round-trip with follow-up

1. Edit the code, Re-run successfully (Data tab shows new values)
2. Ask a follow-up question in the QueryInput, e.g. "show me the latest results"

**Pass:** the new analysis uses the latest computed values from the rerun (verifiable via the artifacts cache).

## API contract

### Request

```http
POST /api/query/rerun
Content-Type: application/json

{
  "csv_id": "...",
  "code": "import pandas as pd\n...",
  "sandbox_runtime": "docker"   // optional
}
```

### Response (success)

```json
{
  "ok": true,
  "artifacts": {
    "code": "...",
    "question": "...",
    "results": { ... },
    "chart_data": { ... },
    "datasets": { ... },
    "execution_ms": 1234,
    "sql": "..."   // preserved from prior artifacts (may be undefined)
  }
}
```

### Response (sandbox error)

HTTP 422 with `{ "error": "<exception message>" }` — surfaced inline in the editor toolbar.

### Response (other errors)

- 400 — missing `csv_id` or `code`
- 404 — csv data expired (user must re-upload)
- 500 — unexpected server error

## Known limitations / non-goals

- **No dashboard re-compose.** Editing code → seeing fresh dashboard requires asking a follow-up question. v2 will refactor the UI-compose step into a reusable function and wire it into rerun.
- **SQL is read-only.** Warehouse SQL editing + re-execution → CSV → analysis pipeline is deferred to v2.
- **No undo history** beyond the single Discard action. Save-as-draft is a future feature.
- **No syntax error detection** before submission — errors only surface after sandbox execution.
- **No autocomplete or LSP-style intellisense** — basic CodeMirror setup only.
- **Bundle weight:** ~150 KB additional gzipped for CodeMirror + 2 language packages + oneDark theme. Lazy-loaded so the cost is only paid on first Artifacts-panel open.
